## Chronicles

A **chronicle** is a game version. Every API route includes the chronicle in the URL path:

```
/api/[chronicle]/items
/api/[chronicle]/npcs
/api/[chronicle]/quests
```

Today only `interlude` is supported. When more chronicles ship later, they'll coexist at the same URL shape — your code will work with a different chronicle by changing the path segment.

## Public vs raw

Two layers, side by side, with different purposes:

### Public endpoints

Cleaned, deduplicated, and cross-linked. This is what you should use to build.

- **Where:** `/api/[chronicle]/items`, `/api/[chronicle]/npcs`, `/api/[chronicle]/quests`, etc.
- **What it does for you:**
  - **Deduplication** — multiple source NPC rows with the same name are merged into one record
  - **Normalization** — trimmed whitespace, sensible rounding, consistent null vs missing
  - **Enrichment** — cross-links to related drops, shops, quests, and sets
  - **Grouping** — type-specific blocks (category, stats, shots, etc.)
- **Stability:** treat the response shape as a stable contract. Field additions are possible; renames or removals are not done lightly.

### Raw endpoints

Source-faithful records, useful for auditing, debugging, or comparing against the upstream datapack.

- **Where:** `/api/[chronicle]/raw/npcs`, `/api/[chronicle]/raw/monsters`, plus their `:id` and spawn variants.
- **Shape:** mirrors the source data closely. Treat it as best-effort, not as a stable contract — parser improvements may change field names.

## Where the data comes from

The API doesn't parse XML or game files at request time. Instead:

1. A build step parses the **aCis Interlude datapack** (XML) and optional **Lineage 2 client DAT files**.
2. Output is written to `data/generated/interlude/*.json`.
3. Those JSON files are committed to the repo and served as-is.

Practical implications:

- **Fast** — no parsing on the request path.
- **Stable between deploys** — data only changes when the JSON is regenerated and shipped.
- **Auditable** — every data change is visible in git diffs.

### aCis as the source of truth

The API surfaces what aCis provides — it doesn't synthesize values or reconcile with other databases. If you see a difference from L2Hub, PTS, L2Wiki, or another source, that's a source difference, not an API bug. Other references may use different datapacks or apply their own corrections.

### Optional client DAT files

Selected DAT files (icon filenames, descriptions) are pulled from the public game client when available. When they're not, those fields are simply `null`. The dataset still covers everything the datapack itself contains.
