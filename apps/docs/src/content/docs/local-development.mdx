---
title: Local Development
description: Run the API locally for development and testing
---

The generated dataset is committed to the repository, so you can run the full API without needing a local datapack.

## Clone and install

\`\`\`bash
git clone https://github.com/cuteshaun/lineage2-api
cd lineage2-api
pnpm install
\`\`\`

## Start the development server

\`\`\`bash
pnpm dev
\`\`\`

The API will be available at **http://localhost:3000/api/interlude/...**.

## Building for production

\`\`\`bash
pnpm build
pnpm start
\`\`\`

## Regenerating the dataset

The \`data/generated/interlude/\` JSON files are the source of truth the API serves. To regenerate them:

\`\`\`bash
pnpm build:data
\`\`\`

This command requires:
- A local **aCis Interlude datapack** checkout configured in \`scripts/chronicle-sources.ts\`
- Optionally, Lineage 2 client **DAT files** for enhanced data extraction (icon filenames, descriptions, etc.)

The datapack and DAT files are not redistributed. After regenerating, the JSON diff is reviewed in PR alongside any parser changes—the dataset is an audited artifact.

## Running tests

\`\`\`bash
pnpm test
\`\`\`

Runs the full test suite including snapshot tests for DTO contracts.

## Linting and type checking

\`\`\`bash
pnpm lint
pnpm typecheck
\`\`\`

## Project structure

- \`src/\` — Next.js API routes and DTOs
- \`data/generated/\` — Pre-built JSON dataset (committed to git)
- \`scripts/\` — Datapack parsers and data generation
- \`tests/\` — Snapshot tests and integration tests
- \`public/\` — Static assets

## Contributing

Pull requests welcome! Keep in mind:
- Data changes are audited through git diffs
- DTO changes require snapshot test updates
- Parser improvements should include test cases
- The dataset reflects aCis Interlude as the source of truth
