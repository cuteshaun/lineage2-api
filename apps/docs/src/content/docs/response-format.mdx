---
title: Response Format
description: Envelopes, pagination, errors, caching, and the public vs raw distinction
---

Every successful response is wrapped in a `data` envelope. **Always read from `data`** — root-level keys aren't part of the contract.

## Single resource

```json
{
  "data": {
    "id": 57,
    "name": "Adena",
    "type": "etcitem"
  }
}
```

## List resource

List endpoints return an array in `data` plus a `meta` object with pagination info:

```json
{
  "data": [
    { "id": 57, "name": "Adena" },
    { "id": 58, "name": "Coin" }
  ],
  "meta": {
    "total": 9206,
    "limit": 50,
    "offset": 0
  }
}
```

## Pagination

List endpoints accept `limit` and `offset`:

```
GET /api/interlude/items?limit=10&offset=20
```

- `limit` — records per page. Default `50`, max `200`.
- `offset` — records to skip. Default `0`.

Use `total` to page through results: `Math.ceil(total / limit)`. `armor-sets`, `locations`, and `regions` return everything in one response and ignore these parameters.

## Errors

Failed requests return a flat `error` message and a `status` code:

```json
{
  "error": "Invalid id: abc",
  "status": 400
}
```

| Status | Meaning |
|--------|---------|
| `200` | Success |
| `400` | Bad request (e.g. invalid id) |
| `404` | Resource or chronicle not found |
| `500` | Server error |

## Caching

Successful responses are CDN-cacheable; data is immutable per deploy.

```
Cache-Control: public, max-age=300, s-maxage=86400, stale-while-revalidate=604800
```

Error responses are never cached:

```
Cache-Control: no-store
```

CORS is open (`Access-Control-Allow-Origin: *`) and no authentication is required, so the API works directly from a browser.

## Public vs raw

The API exposes two layers:

- **Public endpoints** (`/api/interlude/npcs`, …) are cleaned, normalized, deduplicated, and cross-linked. **Apps, tools, websites, and Discord bots should use these by default.**
- **Raw endpoints** (`/api/interlude/raw/npcs`, …) stay closer to the source data and are mainly for auditing or debugging. Treat their shape as best-effort, not a stable contract.
